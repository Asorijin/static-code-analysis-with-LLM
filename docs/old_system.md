# 2 系统组件设计

## 2.1 CCI (Code Change Intention component)

代码更改意向组件，将原始的 commit message 和 diff 作为输入，根据提前设定的 prompt 输出一个结构化的摘要，利用 LLM 抽象出代码提交背后的意图。

**输出结果分为三部分：**

1. **代码更改摘要**：提炼出代码更改的主要操作，即识别有效更改部分，并总结代码片段中不同种类的代码更改

2. **代码更改目的**：推理代码更改的原因，在这一步将提交做出分类，比如重构、功能增强或漏洞修复

3. **代码更改影响**：评估更改导致的后果，包括潜在的影响。在这一步捕获与安全相关的更新和更新导致的潜在风险或潜在修复

---

## 2.2 DA (Development Artifact)

开发组件，用于继承外部开发组件的信息，比如 IR/PR，进一步分析。为了避免分析不相关的信息，如问题报告模板或 CI/CD 通知，使用提前设定的 prompt 指导 LLM 分析。分析结果分为三部分，同上。

---

## 2.3 HV (Historical Vulnerability)

历史漏洞检索组件，用于检索类似的漏洞修复提交，以丰富给定的提交信息。

### 数据库构建流程

在使用 HV 组件之前，需要先构建一个历史漏洞修复数据库：

1. 从 NVD 等漏洞数据库中获取历史漏洞修复信息（除上文提到过的信息，还包括 CVE ID、CVE 描述等）
2. 使用 CCI 组件生成三方面摘要
3. 使用向量嵌入模型将以上信息全部嵌入向量数据库，构建完毕

### 处理新提交

使用 CCI 组件获取三方面摘要，然后从 HV 中检索相似实例。

---

## 2.4 CAVFD

将以上步骤中收集到的所有输出，以及提交的代码更改和 IR/PR，组合成一个全面的 LLM 提示，确保 LLM 可以访问所有相关特征。遵循多维方法根据给定的 prompt 进行结构化分析，得到结果：判断该提交是否为漏洞修复提交，以及原因分析。
